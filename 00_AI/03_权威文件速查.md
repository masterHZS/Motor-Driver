### 生成器管线（原理图是怎么来的）

设计数据只改一处：`01_PCB/Motor-project/_生成器_V3.1/design.mjs`（★ 单一数据源：元件表 + 网络表 + 引脚分配）。管线如下：

| 脚本 | 作用 |
|---|---|
| `solve-pins.mjs` | 引脚分配求解器（穷举全部合法解） |
| `check-design.mjs` | 电气自检（位号唯一 / 引脚全覆盖 / PWM↔AF 一致 / **封装白名单硬拦截**） |
| `layout.mjs` + `kicad.mjs` | 功能块版面 → 生成 `.kicad_sch` |
| `build.mjs` | ★ 构建 + 独立重新解析做端到端校验 + 导出网表/BOM + 自动用 `kicad-cli` 重出 ERC 与官方网表到 `Motor-analysis/`（无 KiCad 时告警跳过） |
| `render.mjs` / `raster.mjs` | 渲染 SVG → PNG |
| `check-wires.mjs` | 走线体检（列出全部直连走线及端点） |

- 活跃生成器只保留 `_生成器_V3.1/`；`_生成器/`、`_生成器_备份_改画法前/`、`_生成器_改画法_半成品/`、`_生成器_改画法前_now/` 是历史，只作追溯。
- 独立审核脚本：`01_PCB/Motor-analysis/audit-*.mjs`（+ `_afparse.mjs`、`_pinout.mjs`、`_solve-keep-analog.mjs`）。

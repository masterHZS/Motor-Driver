## 1. 【阻断 · 必须最先修】A 相低边选错引脚：**P34 没有 TIM4_CHB**

> 这是本次审核**最重要**的发现，优先级高于其余全部条目 ——
> 因为它可能引发**引脚表整体重排**，其余修改都要在它定案之后再做。

### 现象

引脚定稿表把 A 相低边（`PWM_AL` → FD6288T 的 `LIN1`）分配给了 **P34（脚1）**：

```c
/* 03_审核/HC32F005_引脚分配.md:185 */
Gpio_SetAfMode(GpioPort3, GpioPin4, GpioAf3);   /* P34 = TIM4_CHB  A相低 */
```

### 证据：官方参考手册明确 **P34 没有 TIM4_CHB**

`06_参考资料/芯片知识库/_datasheet/RM_HC32F005_Rev2.50_EN.txt:10687`（§6.5.4.4，
偏移 `0xD0`，复位值 `0x0000 0000`）原文：

```
2:0   P34_sel   Port P34 function selection.
      000: GPIO P34
      001: PCA_CH0         PCA module channel 0 capture / compare signal
      010: Reserved        Reserved
      011: TIM5_CHA        Advanced Timer module channel 1 A signal
      100: TIM0_EXT        Timer0 module external clock input signal
      101: TIM4_CHA        Advanced Timer module channel 0 A signal
      110: Reserved        Reserved
      111: TIM1_TOG        Timer1 module toggle signal
```

**P34 的 8 种 `SEL` 取值里根本没有 `TIM4_CHB`**（只有 `TIM5_CHA`(011) 和 `TIM4_CHA`(101)）。

对完整端口功能对照表（`_t76.txt`，按固定列位严格解析，脚本 `03_审核/_afparse.mjs`）做反向索引：

| 定时器通道 | 可用的 (引脚, SEL) |
|---|---|
| `TIM4_CHA` | **P34(sel5)**, P23(sel3), P26(sel2) |
| `TIM4_CHB` | P35(sel5), **P15(sel3)**, P23(sel2), P24(sel1) |
| `TIM5_CHA` | **P34(sel3)**, P36(sel5), P25(sel3), P27/SWDIO(sel2) |
| `TIM5_CHB` | P01(sel5), P24(sel2), **P26(sel3)**, P33(sel3) |
| `TIM6_CHA` | P36(sel2), P02(sel5), P23(sel1), P27/SWDIO(sel3) |
| `TIM6_CHB` | P35(sel2), P03(sel3), **P32(sel3)** |

→ **`P34_SEL=3` 得到的是 `TIM5_CHA`，不是 `TIM4_CHB`。**

### 后果

本方案的核心卖点是「**三颗 ADT 各负责一相的完整互补对，从而都能用硬件死区**」
（`HC32F005_引脚分配.md:71-72`）。但：

| 相 | 高边 | 低边 | 是否同一颗 ADT 的互补对 |
|---|---|---|---|
| A | P23 = `TIM4_CHA` | **P34 = 无 `TIM4_CHB`** ✗ | ❌ **不成对** |
| B | P25 = `TIM5_CHA` | P26 = `TIM5_CHB` | ✅ |
| C | P36 = `TIM6_CHA` | P32 = `TIM6_CHB` | ✅ |

A 相**拿不到硬件互补输出**，也就没有硬件死区。
`check-design.mjs` 却打印「三相互补对：A=TIM4(P23/P34) ✓」——
因为它是**按 `design.mjs` 里自己写的注释/字段判断的，没有回查寄存器定义**，
所以这条自检给出了**假阳性**。

> 硬件兜底：FD6288T 自带 **200 ns 死区 + 直通防止**（见 §9.4），
> 所以 A 相不会因为缺硬件死区而直通炸管。
> 但**设计文档承诺的特性没有实现**，且固件初始化会直接踩坑
> （按 `GpioAf3` 配置 P34 → 实际选中 `TIM5_CHA` → **B 相高边的通道被 A 相低边抢走**，
> 结果是 A 相低边没波形、B 相高边被 A 相的定时器驱动 → **换相逻辑彻底错乱**）。

### 修法

`TIM4_CHB` 在扣除已占用脚后可用的**唯一**选择是 **P15**：

| 候选 | 现状 | 可用？ |
|---|---|---|
| P23 | 已给 A 相高边 `TIM4_CHA` | ✗ |
| P24 | 已给 A 相电压 ADC（AIN0） | ✗ |
| P35 | 已给母线电流 ADC（AIN5） | ✗ |
| **P15** | **当前是 no-connect 空闲脚** | ✅ |

```js
/* design.mjs：P15 从空闲变为 A 相低边 */
PWM_AL: ['U5.11', 'R36.1', 'TP13.1'],        // U5.11 = TSSOP20 脚11 = P15（原为 no-connect）
/* NO_CONNECT 里删掉 'U5.11'，只留 'U5.10'(P03) */
```

配套改动：
1. `PIN_NAMES.MCU` 里脚 11 保持 `'P15'`，但**新增复用说明** `P15 = TIM4_CHB @SEL3`；
2. `NO_CONNECT` 由 `['U5.10','U5.11']` 改为 `['U5.10']`（**只剩 P03 一个空闲脚**）；
3. `HC32F005_引脚分配.md` §5 的固件代码改成
   `Gpio_SetAfMode(GpioPort1, GpioPin5, GpioAf3);  /* P15 = TIM4_CHB @SEL3 */`；
4. **重新跑 `solve-pins.mjs` 穷举**，确认 P15 方案下「三相互补对 + 5 路模拟量不冲突」仍然成立；
5. `check-design.mjs` 增加一条**真正回查 AF 表**的校验，
   把「PWM 网络 ↔ 引脚 ↔ 定时器通道」与参考手册的 `Pxx_SEL` 表对拍，避免同类错误再漏过。

> ⚠️ **注意 `SEL` 号与 `GpioAfN` 枚举可能不是同一套编号。**
> 官方手册对 P23 是 `011: TIM4_CHA`，而 `HC32F005_引脚分配.md:184` 写的是 `GpioAf3` —— 恰好对上；
> 但 P34 手册是 `101: TIM4_CHA`，文档却写「TIM4_CHB @AF3」。**说明编号体系在个别脚上被搞混了。**
> 定案前请以 DDL 的 `gpio.h` 里 `en_gpio_af_t` 枚举定义 + 手册 `Pxx_SEL` 表**双向核对**，
> 确认 `GpioAf3` 到底对应 `SEL=3` 还是别的值。

## 2. 【严重 · 已修复】INA181A2 引脚号完全错位 —— 电流采样电路原本不工作

> 本条与 §1 是**同一类错误**（生成器符号库里写错的引脚数据），同等严重；
> 区别是本条在**硬件**层面、可直接查表判定，因此**本次审核已直接修复**。

### 现象

`design.mjs` 的 `INA181` 符号引脚表把 TI 的引脚号写**完全错位**了：

```js
/* 修复前（错） */
INA181: { 1: 'IN+', 2: 'IN-', 3: 'REF', 4: 'GND', 5: 'OUT', 6: 'VS' }
```

### 证据：TI 官方文档明确真实引脚

`TI SBOA386B` §4.5「INA181-Q1, SOT-23-6 Package」的 *Pin FMA* 表（PIN NAME / PIN NO. 两列）：

| Pin Name | Pin No. |
|---|---|
| **OUT** | **1** |
| **GND** | **2** |
| **IN+** | **3** |
| **IN−** | **4** |
| **REF** | **5** |
| **VS** | **6** |

即真实排列 `1=OUT 2=GND 3=IN+ 4=IN− 5=REF 6=VS`。
来源：<https://www.ti.com.cn/document-viewer/cn/lit/html/SBOA386B/GUID-BFE91D0B-17F5-4A6F-ABBA-897AF10D5A86>
（与 LCSC 货号 `C2058784` 的嘉立创官方符号一致）

### 后果：修复前电路**完全不工作**

修复前各网络（KiCad 官方网表已证实）：

```
ISENSE_P → U3.1   ← 真实是 OUT（放大器输出），被接到分流电阻节点 LS_STAR
ISENSE_N → U3.2   ← 真实是 GND
I_SENSE  → U3.5   ← 真实是 REF，却被接到 MCU 的 ADC
PGND     → U3.3   ← 真实是 IN+，被接地
PGND     → U3.4   ← 真实是 IN−，被接地
VDD_3V3  → U3.6   ← 真实是 VS（只有这个对了）
```

四项致命后果：

1. **放大器输出（pin 1 = OUT）被接到分流电阻节点**，永远到不了 ADC；
2. **ADC 接的是 `REF`（pin 5）**，采到的是基准脚电压而非输出；
3. **两个差分输入 `IN+`/`IN−` 都接在 PGND 上**（同为地电位），差分输入为 0；
4. 本设计**没有过流硬件刹车**（`说明.md` §6.2：无 VC 刹车），
   过流保护**完全依赖软件读 ADC 限流**。电流采样失效 ⇒ **整板失去过流保护**，
   只剩 FD6288T 自带 SCP 兜底，13 A 过流点与 18 A 堵转均不受控。

> ⚠️ `build.mjs` 的端到端自检**照样全绿** —— 因为它只检查
> 「原理图 ↔ `design.mjs`」是否一致，而**两边用的是同一个错引脚表**。
> 这是「自证」的典型盲区，也是本次审核引入外部证据（TI 官方文档）的价值所在。

### 已执行的修复

| 文件 | 改动 |
|---|---|
| `01_工程/_生成器/kicad.mjs` | `SYMDEFS.INA181.pins` 引脚号改为 `3=IN+ / 4=IN− / 5=REF / 2=GND / 1=OUT / 6=VS`（**几何位置不变，仅修正「编号↔功能」对应**），并加勘误注释 |
| `01_工程/_生成器/design.mjs` | `PIN_NAMES.INA181` 同步改为 `{1:'OUT',2:'GND',3:'IN+',4:'IN-',5:'REF',6:'VS'}` |
| `01_工程/_生成器/design.mjs` | `ISENSE_P`：`U3.1`→**`U3.3`**；`ISENSE_N`：`U3.2`→**`U3.4`**；`I_SENSE`：`U3.5`→**`U3.1`** |

```
DRV_HIN2:  R37.2  U1.2
DRV_HIN3:  R39.2  U1.3
DRV_LIN1:  R36.2  U1.4
DRV_LIN2:  R38.2  U1.5
DRV_LIN3:  R40.2  U1.6
```

六个输入各只有一只 **100 Ω 串阻**（`R35–R40`），**驱动器一侧没有任何下拉**。

### 证据：三份项目自己的文档都要求必须加，但设计里没有

| 出处 | 原文 |
|---|---|
| `03_审核/HC32F005_引脚分配.md:144` | 「**下拉 10 kΩ × 6** — ⚠️ **MCU 复位期间 IO 为高阻**，无下拉则 HIN/LIN 浮空 → **上下桥直通炸管。一个都不能省**」 |
| `06_参考资料/芯片知识库/FD6288T.md:92` | 「`HINn` 与 `LINn` 不可同时为高…原设计输入无下拉 → **必须补 10 kΩ 下拉**」 |
| `03_审核/修复方案.md:30,264` | 「每根输入线在驱动器一侧加 **10 kΩ 下拉到 GND**」「主控复位 / 程序未跑 / 排线松脱时，驱动器输入被强制为低，避免上下桥直通炸管」 |

而且这在 V2.0 里**是实现了的**（见 `V2.0_设计规格与计算书.md:157`：六路各加 10 kΩ 下拉）。
V3.0 把六路 PWM 改为 MCU 直连时**把这 12 只（6 串阻 + 6 下拉）里的下漏掉了**。

### 为什么 `R7/R8/R9`（20 kΩ 栅源下拉）不能替代

`R7–R9` 挂在 **MOSFET 的 G↔S** 上，即**驱动器输出的下游**。
它防的是「MOSFET 栅极浮空」，**防不了「驱动器输入浮空」**：
输入浮空时 FD6288T 内部输出级可能翻转 → 栅极被主动驱动 → 与下拉无关。

### 严重性评定（**已考虑有利于设计方的因素**）

FD6288T 官方产品页明确写着**内置直通防止（interlock）+ 200 ns 死区**，
所以**浮空输入不会直接造成上下桥直通炸管** —— 这一点比项目文档的警告要乐观。

但仍有真实危害：

1. **意外换相**：MCU 复位/烧录/固件未跑时 IO 为高阻，浮空输入若被噪声/漏电拉高，
   驱动器会**输出有效的栅极驱动**，电机可能意外通电、抖动、甚至堵转发热。
2. **静态功耗与发热**：输入停在阈值附近时输出级可能线性区振荡。
3. **成本极低**：6 只 0603 10 kΩ，BOM 里 `C25804`（10 kΩ 0603）**已经在用**（`R18/R20/R22/R31`），
   加 6 只不增加新料号、不增加采购行。

→ **定级：严重（必须修）。** 不是因为「一定会炸管」，而是因为
**项目自己的三份文档把它列为 P0 必做项，而 V3.0 漏做且无人发现**，
且 MCU 复位期间处于无保护状态。

### 修法（推荐 A）

**A（推荐，与 V2.0 一致）**：在 `design.mjs` 为六路各加一只 10 kΩ 下拉，
紧贴 U1 引脚到 **PGND**（COM 的地）：

```js
/* 元件表新增 */
{ ref: 'R41', val: '10kΩ', sym: 'R', fp: 'R0603', desc: '★HIN1 下拉（防输入浮空）' },
{ ref: 'R42', val: '10kΩ', sym: 'R', fp: 'R0603', desc: '★LIN1 下拉' },
{ ref: 'R43', val: '10kΩ', sym: 'R', fp: 'R0603', desc: '★HIN2 下拉' },
{ ref: 'R44', val: '10kΩ', sym: 'R', fp: 'R0603', desc: '★LIN2 下拉' },
{ ref: 'R45', val: '10kΩ', sym: 'R', fp: 'R0603', desc: '★HIN3 下拉' },
{ ref: 'R46', val: '10kΩ', sym: 'R', fp: 'R0603', desc: '★LIN3 下拉' },

/* 网络表：加进已有的驱动器输入网络 */
DRV_HIN1: ['R35.2', 'U1.1', 'R41.1'],
DRV_LIN1: ['R36.2', 'U1.4', 'R42.1'],
DRV_HIN2: ['R37.2', 'U1.2', 'R43.1'],
DRV_LIN2: ['R38.2', 'U1.5', 'R44.1'],
DRV_HIN3: ['R39.2', 'U1.3', 'R45.1'],
DRV_LIN3: ['R40.2', 'U1.6', 'R46.1'],

/* PGND 增加 R41.2 R42.2 R43.2 R44.2 R45.2 R46.2 */
```

放在 **DRV_* 网络**（驱动器输入侧）而不是 `PWM_*` 网络（MCU 输出侧）—— 必须紧贴 U1 引脚。
`R41–R46` 同时在 `LCSC` 里补 `'C25804'`（10 kΩ 0603，已在用）。

**B（次选，零硬件改动）**：固件在 `Gpio_Init` 时把六路 PWM 的**内部下拉使能**
（`PxPD=1`，HC32F005 内部下拉典型 40 kΩ，见 `HC32F005_引脚与复用.md:810`）。
⚠️ 但这**不能覆盖 MCU 复位期间**（复位时 IO 仍是高阻），所以**只有 A 才真正闭环**。

## 4. 【严重 · 必须修】12 V 辅助电源在 **3S（9.0–12.6 V）下拿不到 12 V**

### 现象

母线设计窗口是 **9.0–16.8 V（3S + 4S）**（`电机参数.md:62`），
但 `XL7005A` 被设为**降压输出 12.07 V**：

```
VOUT = 1.25 × (1 + 8.66k/1k) = 12.075 V      （R10/R11，design.mjs:67-68）
```

XL7005A 是**降压（buck）** 拓扑，`Vout < Vin` 是硬约束。12.1 V 输出需要的最低母线：

| 依据（官方数据手册 Rev 1.9） | 所需最低母线 |
|---|---|
| 最小压降 **2 V** | **≥ 14.1 V** |
| 最大占空比 **90 %** | ≥ 13.4 V（未计损耗） |

**3S 满充只有 12.6 V**，**永远达不到 14.1 V** → 3S 下 VCC 只能跟随母线（≈母线 − 压降），
**压根稳压不出 12 V**。

### 为什么这是「严重」而不是「提示」

VCC 同时给 **FD6288T 的 VCC(7)** 和 **AMS1117-3.3 的输入**：

```
3S 满充 12.6 V → VCC ≈ 10.6 V（跟随）
  ├─ FD6288T：VCC 额定 5.0–20 V（官方产品页）→ 10.6 V 仍可用 ✓
  │    但 **UVLO 阈值未知**（`FD6288T.md:104` 列为待核对）→ 低到多少会锁死无法确认
  └─ AMS1117-3.3：需要 Vout + 压降 ≈ 3.3 + 1.3 = 4.6 V → 10.6 V 够 ✓
    但 AMS1117 从 ~10.6 V 降到 3.3 V，**压差 7.3 V 全变成热**（见 §5）
```

即 3S 下**板子可能还是能跑**（10.6 V > AMS1117 的 4.6 V 门槛），
但**「12 V 轨」这个设计承诺在 3S 下不成立**，
而且**没有任何文档记录这个降级** —— `V3.0_设计规格与计算书.md` §6.1 写的是
「输入范围 5–80 V | 9.0–16.8 V ✅ 全覆盖」，只核对了 XL7005A 的**输入范围**，
**漏掉了 buck 拓扑对压差/占空比的约束**。

该问题**本项目自己已经查出并写进报告**（`03_审核/XL7005A_EN_FB_查证报告.md:275-290`「额外发现 ②：Buck 裕量不足」），
但**没有回流到设计**：`design.mjs` 的 R10/R11 仍是 8.66k/1k，`说明.md` 仍宣称 12 V。

### 修法（三选一，取决于 3S 是否真的要用）

| 方案 | 做法 | 代价 |
|---|---|---|
| **A：只支持 4S** | 把母线窗口改成 **12.0–16.8 V**，并在文档/丝印上写明「不支持 3S」 | 最小改动；但放弃 3S |
| **B：降低 VCC 目标（推荐若必须兼容 3S）** | `R10` 改 **6.8 kΩ** → `Vout = 1.25×(1+6.8) = 9.75 V` | VCC 从 12 V 降到 9.75 V；**FD6288T 在 9.75 V 仍在 5–20 V 内 ✓**，自举电压随之降到 ≈9.4 V，MOSFET 栅压下降 → 需复核 `Rds(on)` 与损耗（`HYG053N10NS1C2` 按 10 V 栅压规格选型即可） |
| **C：母线电容前置升压 / buck-boost** | 增加升压级 | 复杂、成本高，不推荐 |

> ⚠️ 无论选哪个，都必须**实测 FD6288T 的 UVLO 阈值**（`FD6288T.md:104` 待核对项），
> 才能确认 3S 下 VCC 跟随到最低多少时驱动器仍正常工作。

## 5. 【中 · 建议修】AMS1117-3.3 从 12 V 降到 3.3 V，压差 8.7 V 全发热

### 估算

| 负载电流 | 功耗 `(12 − 3.3) × I` | SOT-223 温升（θJA ≈ 60 ℃/W） | 结温（环温 50 ℃） |
|---|---|---|---|
| 11 mA（**文档 §6.1 的辅助电源负载**） | 0.10 W | +6 ℃ | 56 ℃ ✓ |
| 30 mA（加 MCU 动态/UART/ADC） | 0.26 W | +16 ℃ | 66 ℃ ✓ |
| 100 mA | 0.87 W | +52 ℃ | **102 ℃** ⚠️ |
| 200 mA | 1.74 W | +104 ℃ | **154 ℃** ✗ 超 125 ℃ |

**结论**：按文档给出的 11 mA 负载，**当前是安全的**（这是为什么没炸）；
但**余量很窄**，一旦 MCU 侧负载上去（UART 常发、ADC 高速采样、外加传感器），
就会进入 100 ℃+ 区间。AMS1117 的过温保护会介入 → 3.3 V 跌落 → MCU 复位。

**根本矛盾**：用线性稳压器从 12 V 取 3.3 V，效率只有 `3.3/12 = 27.5 %`，
另外 72.5 % 全变成热。这在架构上就不合理。

### 修法（推荐 A）

| 方案 | 做法 | 说明 |
|---|---|---|
| **A（推荐）** | **把 AMS1117 的输入从 VCC(12 V) 改接 VCC_BUS**（9.0–16.8 V） | 压差从 8.7 V 变 5.7–13.5 V —— **更糟**，❌ 不可行 |
| **A′（推荐）** | **改用带使能的同步降压**（如 `MP2359`/`TPS562201`，SOT-23-6，立创有货）从 VCC_BUS 直接出 3.3 V | 效率 ~85 %，发热几乎消失；成本 +1 颗 IC + 电感。**这是正解** |
| **B** | 保留 AMS1117，但**加大铜箔散热**（SOT-223 的 tab 铺 ≥ 100 mm² 铜）并在 §6.1 写明「**VCC 负载 ≤ 50 mA，禁止外挂**」 | 零成本，但把限制硬编码进设计；原理图上已有该警示（§6.1 表格），**建议同步写进 `说明.md` 和丝印** |
| **C** | 把 XL7005A 输出改 5 V，AMS1117 从 5 V 出 3.3 V | 压差 1.7 V → 0.17 W @100 mA ✓；**但 5 V 不够 FD6288T 用？** 5 V 在 5.0–20 V 边界上，且 MOSFET 栅压 5 V 会导致 `Rds(on)` 大幅上升 → ❌ 除非改为两路电源 |

> 若近期不打算改板：**至少执行 B**，并把「≤50 mA」从计算书抄到 `说明.md` §6 和原理图 ⑫ 块说明里。

## 6. 【中 · 建议修】INA181 输入差分滤波电容位置不对（拓扑缺陷）

### 现象

```
LS_STAR ──R32(3 mΩ 分流)── PGND
   │                              │
  R33(10 Ω)                     R34(10 Ω)
   │                              │
ISENSE_P ──┬── U3.1(IN+)     ISENSE_N ──┬── U3.2(IN−)
           │                            │
         C31.1                        C31.2        ← C31 跨在 INA181 输入端
```

`C31`（100 nF）接在 `ISENSE_P ↔ ISENSE_N` 之间，即**跨在放大器输入端**，
而不是**跨在分流电阻两端**。

### 为什么不对

差分输入滤波器（datasheet 推荐拓扑）必须是：

```
分流电阻 ──[R]──┬── IN+          ← 电容在 R 的外侧（分流侧）
                [C]
分流电阻 ──[R]──┴── IN−
```

现在的接法把电容放在 `R` 的**放大器侧**，后果：

1. **两输入端的源阻抗不再匹配**，共模抑制（CMRR）在高频段下降；
2. **高频干扰先进入 R 才被分流**，而 INA181 输入端看到的是电容的**低阻抗**，
   `R` 与 `C` 形成的滤波对**放大器输入**基本失效（放大器被电容旁路）；
3. 真正需要滤掉的**分流电阻上的共模尖峰**（开关噪声）没有被就近旁路。

```js
/* 现状（design.mjs:272-273）——电容跨在放大器侧 */
ISENSE_P:  ['R33.2', 'C31.1', 'U3.1'],
ISENSE_N:  ['R34.2', 'C31.2', 'U3.2'],
```

### 修法

把 C31 移到**分流侧**，即与 `LS_STAR`/`PGND` 的交点同侧：

```js
/* 方式一：C31 跨在分流两端（最标准） */
/* 新增两条网络：分流电阻的高/低侧抽头 */
SHUNT_SNS_P: ['R32.1', 'R33.1', 'C31.1'],    // = LS_STAR 的那一侧（高电位）
SHUNT_SNS_N: ['R32.2', 'R34.1', 'C31.2'],    // = PGND 的那一侧（低电位）
/* 放大器输入侧只剩串阻的尾端（引脚号已按 §2 修正为 3=IN+ / 4=IN−） */
ISENSE_P:    ['R33.2', 'U3.3'],
ISENSE_N:    ['R34.2', 'U3.4'],
```

> 注意：这会让 `C31` 从 `ISENSE_P/N` 网络移走。当前 `ISENSE_P/N` 各有 3 个成员，
> 改完 `R33.2/U3.3` 与 `R34.2/U3.4` 成为 **2 成员网络**，仍合法（不是悬空）。
> ⚠️ 注意：`LS_STAR` 里已有 `R32.1` 与 `R33.1`，可直接复用该网络；
> `PGND` 里也已有 `R32.2` 与 `R34.1`。因此**只需把 `C31.1` 挪到 `LS_STAR`、`C31.2` 挪到 `PGND`**
> 即可，不必新增网络名（改动更小）。

**另一个可选改进**：INA181 的 `IN−` 端建议再加一只电容到地（共模滤波），
但**必须在 `R` 的放大器侧且两路对称**，否则会引入失调。

## 9. 重新评估后**不构成缺陷**的项（避免误报）

审核中一度怀疑、经核实后**排除**的项，一并记录以免后人重复怀疑：

### 9.1 TVS 选 `SMBJ33A`（Vwm 33 V）对 16.8 V 母线 —— **设计者的取舍，可接受**

一开始我按「TVS 的 Vwm 应 ≥1.1× 最高工作电压」判断 33 V 偏大。
但文档 §5.4 明确记录了取舍理由：

> 「必须 `Vwm > 16.8 V` 且 `Vclamp < 100 V`。原 SMBJ43A 在 16.8 V 母线**永不导通** = 没有保护；
> SMBJ18A 太贴；**SMBJ33A 正好**」

即：**刻意避开「Vwm 贴着工作电压导致长期漏电、TVS 加速老化」**，
选一个在正常工况下绝对不导通的档位，把保护留给真正的异常浪涌。
这是**成立的工程取舍**（代价是 17–33 V 区间的瞬态不钳位）。

> 若希望覆盖更低的瞬态，可考虑 **SMBJ20A**（Vwm 20 V，Vbr ≈ 22.2–24.5 V，Vclamp ≈ 32.4 V）——
> 对 16.8 V 母线有 3.2 V 余量，同时把钳位点从 53.3 V 降到 ~32 V。
> 但**这不是缺陷**，是精度/寿命的二次取舍，由使用者决定。

### 9.2 `FD6288T` 的 `COM(8)` 直接接 `PGND` —— **正确**

`FD6288T.md:90` 要求「COM 是逻辑地，必须与功率地**单点星接**，禁止功率回流穿过它」。
本设计的星点是 **`LS_STAR`（低边源极 + 分流电阻上端）**：

```
Q1/Q5/Q4 源极 ─┬─ R7/R8/R9 下端 ─┬─ R32.1（分流）── R32.2 ── PGND
               └── R33.1         │
                                 └─ U1.8(COM) 接 PGND
```

低边栅极驱动回路的地**恰好就是低边源极**，即 `LS_STAR`；
而 `LS_STAR` 经 3 mΩ 分流后才到 PGND（真正的星点）。
**这是教科书级的开尔文接法**，功率回流不穿过 COM。✓

### 9.3 15 A 慢熔保险丝 —— **偏大，但属知情取舍**

- 稳态最恶劣 **8.4 A**（3S 满充，`电机参数.md:63`）→ 15 A 只有 **1.79×** 余量，
  而文档 §5.4 自己写的准则是「取 **1.5–2×**」→ **在下沿，勉强合规**。
- 过流点 13 A **低于**保险丝 15 A → **保险丝永远先于软件限流动作**，
  即保险丝**不能保护 MOSFET**（硬短路时 MOSFET 先炸）。
  但这一点文档已隐性承认（保护主体是「软件限流 + FD6288T 自带 SCP」，见 `说明.md:161`）。
- 保险丝耐压 **32 V** > 母线 16.8 V ✓。

→ 定级「提示」：**建议把 §5.4 的表格补一句「保险丝只保护线路，不保护半导体」**，
避免后人误以为有硬件过流保护。

### 9.4 相电压分压 150 k/10 k + 1 nF —— **正确**

- 分压比 `10/160 = 1/16`，16.8 V → **1.05 V**（12 bit ADC 分辨率 9.8 mV/计数）✓
- 一级 RC 时间常数 `(150k∥10k)×1nF = 9.4 µs` → 对应 17 kHz，
  在 487 Hz 电频率下相移仅 `arctan(487/17000) = 1.64°` ✓（`电机参数.md:98` 已核算）
- ADC 源阻抗：数据手册 `RAIN` 表在 `FADC=150 kHz / M=12` 时允许 **1300 kΩ**，
  本设计等效源阻抗 ≈ **9.4 kΩ** → **余量 138×** ✓

### 9.5 虚拟中性点 3×100 kΩ + 270 pF —— **正确**

时间常数 `(100k∥100k∥100k)×270pF ≈ 33.3k×270pF = 9.0 µs`，
与相电压通道的 9.4 µs **刻意对齐** ✓（`design.mjs:112` 注释即为此意），过零比较无系统性偏差。

### 9.6 `INA181A2` 的 `REF` 接 GND —— **正确（修复后）**

REF 接地 = 单向（单极性）测量，输出 `Vout = 50 × Vshunt`，
低边分流（共模 ≈ 0 V）落在 INA181 共模范围（−0.2 ~ +26 V）内 ✓。
8.8 A → 1.32 V，13 A → 1.95 V，均在 ADC 量程内 ✓；18 A → 2.70 V（超过内部 2.5 V 参考，
即堵转时 ADC 饱和，对「限流」用途可接受）。

> ⚠️ **本条修复前是错的** —— REF（pin 5）当时悬空、输出（pin 1）错接在分流电阻上。
> 详见 §2（已修复：`U3.5 = REF → PGND`，`U3.1 = OUT → ADC`）。

> ⚠️ 唯一残留：计算书 §5.2 的「堵转输出 2.70 V（18 A）→ **需在输出串 10 kΩ + 对 3.3 V 钳位（BAT54S）**」
> 这一条**未在原理图实现**（只有 `R49 = 1 kΩ` + `C34 = 1 nF`，无钳位）。
> 因 INA181 输出上限被自己的 VS = 3.3 V 轨钳住，而 MCU 绝对最大输入为 `VCC+0.3 = 3.6 V`，
> **对 MCU 的实际风险很低**（不是缺陷），但**文档要求的措施缺失** —— 归入 §8 提示项。
> 若追求稳健，可加 BAT54S。

### 9.7 MCU 模拟通道分配 —— **全部正确**

`P24→AIN0`、`P33→AIN3`、`P02→AIN8`、`P35→AIN5`、`P01→AIN7` 与数据手册

## 12. 总体评价

**这张原理图的工程化程度是高的**：单一数据源 + 自动生成 + 端到端自检 + KiCad ERC，
而且**历史踩过的坑（极性、低边源极、AF 号、封装）都真的被吸收进了生成器和知识库**。
本次独立复核**没有发现任何短路、悬空、重复占用或极性错误**，
这在手工画的原理图里几乎不可能做到。

问题集中在**三类**：

1. **「引脚复用能力没有回查官方寄存器定义」** —— §1：`P34` 压根没有 `TIM4_CHB` 这个功能，
   整张引脚表的 A 相都建立在一个不存在的复用能力上。**这是最严重的一类**，
   因为原理图连接是对的、ERC 是干净的、自检也是绿的，**只有回查手册才能发现**。
2. **「从 V2.x 迁移到 V3.0 时的遗漏」** —— §3 的 6 只下拉（V2.0 有、V3.0 漏）
   是典型；§7 的过期审核产物同理。
3. **「拓扑裕量在极端工况下的核算不足」** —— §4 的 3S/12 V 冲突、
   §5 的 LDO 发热、§6 的滤波电容位置。

其中最值得记住的教训是第 1 类：
**`check-design.mjs` 只对着 `design.mjs` 自己的字段做一致性检查，没有回查官方寄存器定义，
所以给出了「三相互补对 ✓」的假阳性。自检的边界 = 设计者自己的认知边界。**
本次审核之所以能抓到，是因为刻意换了三种**不经过生成器**的证据源
（几何重建、KiCad 官方网表、参考手册寄存器表）。

> **建议顺序**：先做 §10 的 P0 三条（尤其第 1 条，它可能引发引脚表重排），
> 再统一重出图；P1 可在打板前一并处理。

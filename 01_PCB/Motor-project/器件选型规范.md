# 器件选型规范（元器件选取方法）

> **适用范围**：本项目（三相无刷电机驱动板）全部电气物料的选择、替换与新增。
> **约束力**：本规范是**硬性准入门槛**，不是建议。任一条不满足 → 该器件不得进入 BOM。
> **执行方式**：`R0`–`R3` 由 `_生成器_V3.1/check-design.mjs` **自动拦截**（不通过则构建失败）；
> `R4`–`R9` 由人工在选型时逐条核对并在 `Motor-analysis/` 留痕。
>
> 建档：V3.0（2026-09-13）｜来源要求：用户指令「所有封装库使用嘉立创有的」
> ✅ **本规范对 V3.0 / V3.1 一体适用**（V3.1 只新增 1 种实物封装 `C1210`，实物封装 19 → **20 种**，见文末变更记录）。

## R0 ★★★ 封装必须来自嘉立创官方库（最高优先级）

**规则原文**：

> **所有元器件的封装，必须使用嘉立创（嘉立创EDA / 立创商城）官方库中已经存在的封装。**
> **准入门槛 = 「立创元件库里有这个元件（自带封装）」；不要求现货有库存。**
> 库存只影响下单交期，不影响能否画进 EDA、能否贴片。
> **若库里根本没有这个型号（或没有带封装的条目），才选用立创有的、可以替代的型号。**
> （**不因为"原型号立创没有"就退回自造封装或外部库** —— 换器件，不换规则。）

**为什么必须是硬门槛**：本项目最终要**导入嘉立创EDA专业版画 PCB 并下单打样/贴片**。
如果封装名是自造的、或拼写与立创库不一致，导入后该元件会**丢失封装**，
轻则要逐个手工补，重则 PCB 上没有焊盘 → **板子作废**。
（V2.0 就踩过这个坑：`03_审核/封装与接口对照表.md` 记录的「元件缺乏封装」问题，91 个位号里有数个对不上。）

### R0.1 官方库与命名依据

| 项 | 内容 |
|---|---|
| 库 | **嘉立创EDA 官方库（立创商城库）**，官方规模 **> 18 万**种封装 |
| 命名规范 | 《嘉立创EDA封装库命名参考规范》（立创商城工程部 + 嘉立创EDA团队） |
| 命名语法 | `封装类型_脚数-体宽-脚距-体长-脚跨距-一脚方位-极性方向_系列名` |
| 实际库内形态 | 常见形如 `R0603`、`TSSOP-20_L6.5-W4.4-P0.65-LS6.4-BL`（`L`=长 `W`=宽 `P`=脚距 `LS`=脚跨距） |
| 出处 | [封装库命名参考规范（官方文档）](https://docs.lceda.cn/cn/PCBLib/PCBLib-Naming-Rule/) |

> ⚠️ **仅凭名字符合语法 ≠ 库里一定有**。语法只能保证「不是乱编的」，**不能证明存在**。
> 真正保证「立创有」的机制是下面 R0.2 —— 那是**唯一可靠**的办法。

### R0.2 唯一可靠的保证机制：绑定 LCSC 料号 ★

**每个元件都必须携带 LCSC 料号（`C` + 数字，如 `C97683`），并在嘉立创EDA里用该料号绑定器件。**

为什么这是唯一可靠的办法：

- 立创EDA 的「**器件属性绑定**」会用 LCSC 料号**自动带出官方封装 + 3D 模型**；
- 带出来的封装**必然存在于官方库**（同一套数据源），从根上消灭「封装找不到」；
- 手填封装名 = 猜；填料号 = 让立创自己给出封装。

**因此本规则的可执行形式是**：

```
每个元件 = 参数值 + LCSC 料号 + 立创官方封装名
            ↑ R0.2 保证可达性      ↑ R0.1 保证一致性（应与料号带出的封装一致）
```

### R0.3 三级验证流程（必须全部走完）

| 级别 | 时机 | 手段 | 通过判据 |
|---|---|---|---|
| **L1** 离线 | 每次改设计 | `node _生成器_V3.1\check-design.mjs` | **封装名命中白名单（R0.4）→ 硬拦截，不在白名单直接构建失败**；另有宽松命名体检（含可疑字符则告警）。<br>⚠️ 刻意**不用死板正则卡语法**：立创实库变体多（`CAP-TH_BD8.0-P3.50-D0.5-FD` 用体径 BD 无 L/W；`IND-SMD_L6.0-W6.0_LPS6225` 以 `_系列名` 结尾），硬卡会造成假失败 |
| **L2** 绑定时 | 导入立创EDA后 | 用 LCSC 料号逐个绑定（封装管理器） | 封装管理器**无「缺失封装」报错**，且自动带出的封装名与本项目记录一致 |
| **L3** 出板前 | 生成 Gerber 前 | PCB 编辑器 3D 预览 + 封装管理器全量检查 | 17 种封装全部有焊盘、无 `--`/`unknown` 封装、3D 模型齐全 |

> **L1 不通过直接构建失败**；L2/L3 在 `03_审核/` 留核对记录。

### R0.4 怎么确认"立创到底有没有这个封装"（用户指令：直接去嘉立创搜）

**不要靠命名规则类推，也不要靠二手资料。** 权威做法是查嘉立创/立创自己的数据。本项目实测可用的办法：

| 办法 | 操作 | 得到什么 |
|---|---|---|
| **① 组件数据接口**（最快、可批量） | 浏览器或脚本访问<br>`https://lceda.cn/api/products/{LCSC货号}/components`<br>（海外版同理：`https://easyeda.com/api/products/{货号}/components`） | 返回 JSON，取 **`result.dataStr.head.c_para.package`** = **立创官方库里的封装名**；<br>同时给 `Manufacturer` / `Manufacturer Part` / `stock`（现货） |
| **② 嘉立创EDA 界面** | 专业版 → 元件库 → 搜型号/货号 → 看"封装"字段 | 同上，人工核对 |
| **③ 立创商城商品页** | `item.szlcsc.com` 搜型号 → 看"商品封装" | 商品级封装名 |

> ⚠️ `so.szlcsc.com` 的搜索页是 JS 渲染的，直接抓取会得到空内容（HTTP 203）——**用①的接口**。

#### R0.6.1 搜索接口不可信，必须回组件接口复核（2026-10-15 新增坑位）

立创的**搜索接口** `https://lceda.cn/api/eda/product/search?keyword=…` 能按关键词给出货号，
但**它返回的 `name` / `catalogName` 不等于器件参数**——实测反例：

| 检索词 | 搜索接口给的货号 | 实际是什么 |
|---|---|---|
| `100nF 0603` | C19702 | **10 µF** 的 `CL10A106KP8NNNC`（容值差 100 倍） |

⇒ **规则**：搜索接口只用来**发现货号**；拿到货号后**必须**再调
`https://lceda.cn/api/products/{货号}/components`，以 **`c_para.package`（官方封装名）** 与
**`Manufacturer Part`（真实型号）** 为准，并回写进 BOM。

**另一处口径差异**：同一货号的**现货数**在「搜索接口」与「组件接口」可能不同
（实例：`HC32F005C6PA` = C784652，一处显示 0、一处显示 897）。
库存只影响交期、不影响准入（R5），但**下单前应复核**。

**工具**：本仓库已提供脚本 `01_PCB/DRV控制板/tools/check-lcsc.mjs`（`node tools/check-lcsc.mjs <C号…>`
或 `--from-config`）——它只走组件接口，逐条打印官方封装名，避免手工抄错。

### R0.6 替代原则：同等优先，无则替代（用户要求）

选型按下面**顺序**决策，**不允许跳到最后一步**：

| 优先级 | 做法 | 说明 |
|---|---|---|
| **① 首选** | 选**参数完全一致**、封装一致、立创有货的原型号 | 最理想，直接绑定货号 |
| **② 次选** | 选**参数可替代**的立创型号（电气参数**满足或优于**原要求） | 见下方判据 |
| **③ 再选** | 若②也没有，**改电路参数**去适配一个立创现成型号 | 必须同步改计算书与核算 |
| ❌ **禁止** | 因"立创没有原型号"而改用自造封装 / 非立创库 | 换器件，不换规则 |

**"可替代"的三条判据（必须全部满足）**：

1. **电气满足**：耐压 ≥ 原要求、电流 ≥ 原要求、功率 ≥ 原要求、精度/温漂不劣于原要求
   （例：MOSFET 若立创无 `HYG053N10NS1C2`，可用 **100 V / ≥60 A / Rds(on) ≤ 6 mΩ** 的 PDFN 5×6 型号替代）
2. **封装可落板**：优先**脚对脚（pin-to-pin）**兼容；若封装不同，必须确认 PCB 能改（新封装尺寸/散热/爬电距离可接受）
3. **功能不缺失**：不能少掉原器件的关键功能
   （例：不能把带 SCP 保护的 FD6288T 换成无保护的三相驱动 —— 本项目**过流保护依赖它**）

**替代必须留痕（R8）**：在 `V3.0_设计规格与计算书.md` 修订摘要记录
「`原型号` → `替代型号`（`LCSC货号`）+ 替代理由 + **差异项**（哪些参数变差了）」。

> ⚠️ **替代的代价要算清**：本项目已有一例——MOSFET 若换 30 V 管，总损耗可从 1.70 W 降到 0.63 W，
> 但这属于**性能变化**，必须回到 `V3.0_设计规格与计算书.md` §4.2 重算，不能只改 BOM。

## R1 封装与器件的物理匹配性

- **引脚数与脚距必须与器件实际一致**（含散热焊盘 EP：XL7005A 的 EP 必须画出来并接地）
- **功率/电压余量**：电阻功率 ≥ 2× 实际功耗；电容耐压 ≥ 1.5× 实际承受电压
  （例：自举电容取 50 V，母线高边陶瓷取 100 V）
- **封装尺寸要能承受功耗**：分流电阻 3 mΩ/2 W 必须用 2512，不能用 1206

## R2 一致性（去重复）

- 同类器件优先复用同一型号，减少 BOM 行数与采购复杂度
- 「同一物理封装只登记一个封装名」**只在立创官方数据证明两者确为同一封装时成立**。

> ★★ **本条曾被误用，务必记住**：`SMA_L4.3-W2.6-LS5.0-RD`（ES1D / C18199158）与
> `SMA_L4.3-W2.6-LS5.2-RD`（SS110-LTP / C85691）**虽然都是 SMA，却是立创库里两个不同的封装**
> （引脚跨距 LS 不同）。曾以"同一物理封装应统一命名"为理由把两者合并成 `LS5.1`，
> **是错的** —— 差点让两个器件的封装都不匹配。
> **判据**：封装名是否该合并，由**立创官方数据**决定，不由"看起来像同一个封装"决定。

## R4 电气余量按最坏情况

选型一律按**最坏工况**核算，不得按典型值：

| 参数 | 本项目取值 | 依据 |
|---|---|---|
| 母线 | 16.8 V（4S 满充） | 上限 |
| 相电流 | 8.8 A 连续 / 13 A 过流 / **18 A 堵转** | `V3.0_设计规格与计算书.md` §5 |
| 环境温度 | 按 40 ℃ 以上降额 | — |

## R5 货源与可获得性

> ⚠️ **R5 是「优选」，不是「准入」**：**没有库存不影响元件能否被选用**（见 R0 规则原文）。
> 库存/交期只影响一次下单的排期，属于采购环节的优化项。

- **优先**选立创商城「现货 + 可贴片（SMT）」的型号（基础库/扩展库均可）
- 避开：停产（EOL）、仅拆机/仅代购的型号
- 每颗关键器件（MCU、栅驱动、MOSFET、LDO）应备一个替代料思路（见 R0.6）

> **实例（本项目）**：`HC32F005C6PA-TSSOP20TR`（立创 `C784652`）**现货为 0**，但**元件库中有该条目且自带封装** `TSSOP-20_L6.5-W4.4-P0.65-LS6.4-BL` → **符合 R0 准入，照常使用**。
> 同系列的 QFN-20 版本（`C440502`，现货 86）与 QFN-24 版本（`C2762083`）**引脚号排列与 TSSOP-20 不同**（见 `06_参考资料/芯片知识库/HC32F005_引脚与复用.md` §QFN20/TSSOP20 引脚号对照），
> 换封装会连带改整个 `MCU 引脚 1..20` 映射，**除非必要否则不动**。

## R6 温度与封装工艺

- 车规/工业级优先；至少 **−40 ~ +85 ℃**
- 手焊优先 0603 及以上、引脚外露封装；QFN/DFN 类须走立创 SMT

## R7 关键器件的「数据手册核实」要求

MCU、栅驱动、MOSFET 等关键器件，**引脚定义与电气参数必须来自官方数据手册/参考手册**，
不得来自二手博客或推算。核实结论写入 `06_参考资料/芯片知识库/[型号].md`。

> 本项目教训：FD6288T 脚序曾出错（见 `FD6288T.md` §4 勘误）；
> 「数据手册第 N 项功能 = AF(N−1)」的推算法在 P32/P33 上是**错的**（手册跳过 Reserved 空档）。

## R9 与生成器的关系

本项目的原理图由 `_生成器_V3.1/design.mjs` **单一数据源**生成。
因此**器件选型 = 修改 `design.mjs` 的元件表**，然后：

```powershell
cd ".\01_PCB\Motor-project"          # 脚本内部用相对路径（原为写死的绝对路径）
node "_生成器_V3.1\check-design.mjs" # ← R0/R2/R3 在此自动拦截，不通过则停
node "_生成器_V3.1\build.mjs"        # 出图 + 端到端校验 + 网表/BOM
```

**不允许**直接编辑 `motor-driver-V3.1.kicad_sch`（会被下次生成覆盖）。

## 附：选型标准流程（每次新增/替换器件走一遍）

```
① 定需求        → 电气参数（电压/电流/功耗/精度）+ 最坏工况（R4）
② 查立创库      → 在立创商城/嘉立创EDA按参数筛选（R5）：
                   ├─ 有完全一样的  → 选它
                   └─ 没有          → 按 R0.6 选「立创有的、可替代的」型号（电气满足 + 封装可落板 + 功能不缺失）
③ 取官方库封装  → 用 LCSC 料号绑定，由立创**自动带出**官方封装名 → 抄进白名单（R0.1 / R0.2 / R0.4）
④ 查数据手册    → 核实引脚与电气参数，写进芯片知识库（R7）※替代料尤其要重新核引脚
⑤ 登记          → 改 design.mjs：val + fp + lcsc（R3）
⑥ 自动拦截      → node check-design.mjs（R0 / R2 / R3）
⑦ 记录变更      → 修订摘要，替代料必须写差异项（R0.6 / R8）
```

## 附二：规则有效性验证记录

**一条从未失败过的规则等于没有规则**，因此 R0 的白名单闸门做过注入测试：

| 测试 | 操作 | 结果 |
|---|---|---|
| 注入 | 把 `C46` 的封装从 `C0603` 改成 `C0603_JLC_GUESS` | `✗ R0: C46 的封装 "C0603_JLC_GUESS" 不在立创封装白名单 → …`，`check-design.mjs` **exit 1，构建失败** ✅ |
| 还原 | 恢复原文件（SHA256 校验一致） | `✓ 电气自检通过`，exit 0 ✅ |

> 注：该测试前两次尝试是**无效测试**，记录于此以免重犯：
> ① `Set-Content -Encoding utf8NoBOM` 在本机 Windows PowerShell 5.1 不存在 → 文件根本没被改写，
>    "哈希一致" 是因为两次都没动；② 替换串多写一个引号 → 造成 JS 语法错误，
>    exit 1 是**语法错误**而非闸门拦截。**验证拦截能力时，必须确认"注入确实生效"。**

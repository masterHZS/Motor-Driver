# F005 无感六步闭环与上位机控制

> 2026-10-14：后续开发主控按用户决定采用HC32F005C6PA。固件0x0202/build ID 9。
> 当前板上005此前已拆，是否装回尚未确认；本轮没有烧录或运行电机。
> 本版本需要新增 **VN → P34（TSSOP20第1脚）** 飞线，用户已明确确认。

## 1. 上位机操作

- UART0：9600-8N1，Modbus-RTU地址1，FC03/FC06。
- 每次复位后前10秒保留SWD，之后P27切换为UART0_RXD。**这是用户2026-10-14明确指定的例外**，覆盖旧“005运行固件不释放SWD”的约束；P31不配置为外设输出。复位/重新上电恢复10秒窗口。
- USB-TTL TX → TP3/P27；USB-TTL RX ← TP6/P14；GND → TP2/AGND。
- 烧录时断开USB-TTL TX与P27的连接，避免其输出与SWDIO冲突；供电窗口与SWD可靠性需要实板确认。
- 连接后点击“启动”，上位机会先下发当前目标比例，再发启动。目标为0时保持关断；启动请求已设置后，抬高推杆进入启动过程。
- 启动中可以调整推杆：改变功率限幅与启动目标频率；闭环后由BEMF反馈和速度PI调节功率。
- 推杆到0、停车/散热、紧急停车均关断；停机后抬高目标不会自行重启，需要再次启动。
- 本版速度目标以**电频率**表示，0为停车，1–100按 `5 + 295×比例/100` 电Hz映射。300电Hz只是开发限幅，不代表电机已达到该工作点。
- 上位机显示寄存器0x0006的BEMF估计电频率；启动强制换相频率不冒充反馈。机械RPM=`60×电Hz/极对数`，12个线圈不能确定极对数，当前不显示推算RPM。

## 2. 新增采样线

断电后从 **C24接VN网络的一端**（不是接AGND的一端）飞线到 **U5第1脚/P34/AIN4**。不要凭PCB方位猜焊盘，也不要把相线/12 V直接送GPIO。此改动是实板飞线方案，冻结原理图没有被静默重画。

原三相仍为TP7→P24/AIN0、TP8→P33/AIN3、TP9→P02/AIN8；母线TP11→P01/AIN7，电流TP10→P35/AIN5。005在板上时沿原有走线连接。

## 3. 控制算法

算法对照来源：[AM32 main.c，固定commit 961cb84](https://github.com/am32-firmware/AM32/blob/961cb84f5dd4420f6da127b982a5027b290e2848/Src/main.c)。本机逐项映射见 `../../06_参考资料/开源参考工程/AM32_算法对照/对照说明.md`；该第三方缓存按仓库规则不入Git，其他机器可通过上述链接查看原始参考。保留005官方DDL和六路互补PWM；未把AM32的STM32 HAL或整套固件编入本工程。

- TIM4三角波谷点提交换相，TIM1只请求下一步；换相时间戳记录在真正提交处。
- TIM4比较D=300的下降段启动BEMF帧，顺序VN→浮空相→VN，并插值参考到浮空相采样时间。不再用占空比乘母线估计门限。
- 每次转换完成由ADC中断处理；核查步骤标记、PWM关断窗口和帧时长，丢弃跨步/过期帧。
- 过零要求消隐后先稳定处于预期一侧，再连续两次处于另一侧；每步只产生一次事件，并检查事件时间范围。
- 至少完成36步启动换相，再连续6步有效反馈才能切闭环；过零时间间隔估计下一步周期，过零后30电角度用TIM1安排换相。
- 启动限时8秒（不含HOLD/预充/定位），反馈丢失关断。持续开环模式禁止构建；受限启动阶段仅用于建立反馈，不允许永久停留。
- 闭环每10ms执行整数速度PI，目标变化限制30电Hz/s，积分抗饱和。初始PI增益为待实板整定值，软件测试不能证明齿轮泵负载稳定性。
- Modbus发送改为非阻塞；STOP/FAULT清除未提交换相，防止下一谷点重新输出。

## 4. 寄存器

| 地址 | 说明 |
|---|---|
| 0x0000 | 输出控制启动/运行状态；1不能单独证明转轴已经转动 |
| 0x0001 | 启动请求，写0关断 |
| 0x0002 | 目标速度比例0–100 |
| 0x0003 | PWM频率，仅20000 Hz |
| 0x0004 | 实际功率占空比，整数百分比；PWM内部支持千分比调节 |
| 0x0005 | 故障位 |
| 0x0006 | BEMF反馈电Hz，未进入闭环时为0 |
| 0x0007 | 0x0202 |
| 0x0008 / 0x0009 | 通信错误/成功计数 |

故障：0x0001非法命令、0x0002通信超时、0x0004过流、0x0008欠压、0x0010过压、0x0020保留堵转、0x0040反馈丢失/启动超时、0x0080 ADC超时。故障锁存，当前通过复位恢复，不自动重试启动。

## 5. 构建与软件回归

```powershell
.\build_comms.ps1
# 默认无感闭环、SWD窗口10000ms、20kHz，最大15%、定位5%、启动最大10%
# 产物：build_comms/comms.hex / comms.bin / comms.elf

python -m pip install unicorn
python .\tests\test_firmware.py --toolchain-bin <GCC的bin目录>
```

使用现有GCC 12.3.1、官方HC32F005 DDL Rev2.0.0、-O2，保留调试符号。Unicorn仅是PC测试依赖，不进入固件。测试执行实际ARM镜像，模拟寄存器；**没有模拟实际ADC、电机、MOSFET或栅极驱动时序**。

链接脚本将0x20000F00–0x20000FFF留作SWD marker，栈顶改到0x20000F00，避免诊断覆盖栈。

## 6. 实板验证边界

必须继续使用12.0–16.8 V、外部5 A限流，首转14.5–15.0 V。母线软件欠压仍沿用13 V，未擅自修改待确认的设计门限。

母线电流改由PWM峰点硬件触发ADC；**低占空比时ON采样窗口可能不足，软件电流值不能作为可靠相电流限流证明**，外部限流不可省。两次VN采样插值不能消除模拟网络本身的相位差；VN/三相滤波匹配、PWM真实占空比与死区、自举、电流窗口、目标速度带载跟踪仍需实板验证。

### 2.1 `DDL_DEVICE_PACKAGE_HC_K` 是什么封装？

- `【DDL】Drivers/hc32f005/inc/ddl.h:88-94` 只列出**封装代号枚举**：`HC_C=0x00`、`HC_F=0x10`、`HC_J=0x20`、`HC_K=0x30` —— **DDL 里没有"HC_K = 多少引脚"的映射**。
- `【DS】D1:873-880` 型号编码规则：`C: 20Pin`、`P: SOP/TSSOP`、`U: QFN`。
- 综合判断：本 DDL 工程器件为 20 引脚封装（`HC32F005C6PA` = 32 KB Flash / SOP/TSSOP / 20 pin；`HC32F003C4PA` = 16 KB / SOP/TSSOP / 20 pin）。
- **`HC_K` ⟷ 20 引脚是否严格等价：⚠️未确认**（本地无 DDL 封装代号与引脚数的官方对照）。

## 3. Q1：GPIO 总数与端口划分，以及"为什么只有 16 个引脚"

### 3.1 端口结构

| 端口 | 枚举值（= 寄存器块偏移步进） | 每端口位数 | 该端口**实际暴露**的引脚 |
|---|---|---|---|
| Port0 | `GpioPort0 = 0x00u` | 最多 8（位域 P00–P07 的模板） | **P01, P02, P03**（+ **P00**，但 P00 只能作数字输入） |
| Port1 | `GpioPort1 = 0x40u` | 最多 8 | **P14, P15** |
| Port2 | `GpioPort2 = 0x80u` | 最多 8 | **P23, P24, P25, P26, P27** |
| Port3 | `GpioPort3 = 0xc0u` | 最多 8 | **P31, P32, P33, P34, P35, P36** |

**依据**：
- 端口枚举与步进：`【DDL】Drivers/hc32f005/inc/gpio.h:83-89` `en_gpio_port_t`（`0x00/0x40/0x80/0xc0`）；`gpio.h:74` `#define GPIO_GPSZ (0x40u)`。
- 引脚枚举：`【DDL】Drivers/hc32f005/inc/gpio.h:95-105` `en_gpio_pin_t` `GpioPin0..GpioPin7`（**位置编码 = 位号**，不是 0..n 的序号）。
- Port3 只到 P3.6 的硬件事实：`【DDL】Project/hc32f005/hc32f005.h:1314-1322` `stc_gpio_p3dir_field_t` 用 `RESERVED0:1 + P31..P36`；SVD `HC32F005.svd:6444` `P3ICLR resetMask=0x7E`（bit1–bit6）。
- Port2 起点是 P2.3：`【DDL】Project/hc32f005/hc32f005.h:1193-1201` `stc_gpio_p2dir_field_t` 用 `RESERVED0:3 + P23..P27`。
- Port1 只有 P1.4/P1.5：`【DDL】Project/hc32f005/hc32f005.h:1109-1114` `stc_gpio_p1dir_field_t` 用 `RESERVED0:4 + P14,P15`。
- Port0 方向位从 P01 起（P00 无方向位）：`【DDL】Project/hc32f005/hc32f005.h:1013-1019` `stc_gpio_p0dir_field_t` 用 `RESERVED0:1 + P01,P02,P03`；对比 `:1021-1027` `stc_gpio_p0in_field_t` 含 `P00`。

### 3.2 为什么**没有** P00 / P04–P07 / P10–P13 / P16–P17 / P20–P22

**因为物理上不存在**——这不是 DDL 裁剪，而是 20 引脚封装的现实：

| 缺失组 | 结论 | 依据 |
|---|---|---|
| **P00** | 存在，但**与 RESETB 复用**，且**只能作数字输入**（无 DIR/OUT/ADS/PU/PD/OD 位） | `【DS】D1:1110-1115` "RESETB / P00 … P00 数字输入"；`【DDL】Project/hc32f005/hc32f005.h:1015,1031,1039,1047,1055,1063,1071` 全部 `RESERVED0:1`（P00 位被保留）；无需 SEL 寄存器（不能复用输出） |
| **P04–P07** | 芯片无此引脚 | 端口位域模板止于 P03（`【DDL】Project/hc32f005/hc32f005.h:1013-1019`）；`【DS】D1:1107-1551` 引脚功能说明表中无 P04–P07 |
| **P10–P13** | 芯片无此引脚 | `【DDL】Project/hc32f005/hc32f005.h:1109-1114`（P1 从 P14 起）；`【DS】D1` 引脚表无 P10–P13 |
| **P16–P17** | 芯片无此引脚 | 同上（P1 只有 P14/P15） |
| **P20–P22** | 芯片无此引脚 | `【DDL】Project/hc32f005/hc32f005.h:1193-1201`（P2 从 P23 起）；`【DS】D1` 引脚表无 P20–P22 |
| **P30** | 芯片无此引脚 | `【DDL】Project/hc32f005/hc32f005.h:1314-1322`（P3 从 P31 起） |

**"16 个引脚"的完整自证**：`【DDL】Project/hc32f005/hc32f005.h` 中带 `SEL` 位域的引脚类型定义恰好 16 个 ——
`stc_gpio_p01_sel_field_t`(:936)、`p02`(:941)、`p03`(:946)、`p14`(:951)、`p15`(:956)、`p23`(:961)、`p24`(:966)、`p25`(:971)、`p26`(:976)、`p27`(:981)、`p31`(:986)、`p32`(:991)、`p33`(:996)、`p34`(:1001)、`p35`(:1006)、`p36`(:1011)。
SVD 侧同样 16 个 `Pxx_SEL` 寄存器（`【DDL】HC32F005.svd:3970,3988,4006,4024,4042,4060,4078,4096,4114,4132,4150,4168,4186,4204,4222,4240`）。
**所以你最初的发现是正确的**：P01/P02/P03/P14/P15/P23/P24/P25/P26/P27/P31/P32/P33/P34/P35/P36 = 16 个。

> **偏移规律（端口内步进恒为 0x04；端口块起点不连续）**：
>
> | 端口 | SEL 块起始偏移 | 该端口首个带 SEL 的引脚 |
> |---|---|---|
> | Port0 | `0x04` | P01 |
> | Port1 | `0x50` | P14 |
> | Port2 | `0x8C` | P23 |
> | Port3 | `0xC4` | P31 |
>
> 端口内：`偏移 = 端口块起点 + 0x04 × (enPin − 该端口首个引脚的位号)`。
> 例：Port2 的 P27 → `0x8C + 0x04×(7−3) = 0x9C` ✓；Port3 的 P36 → `0xC4 + 0x04×(6−1) = 0xD8` ✓。
> 端口块之间的间隔（`0x50−0x04 = 0x4C`、`0x8C−0x50 = 0x3C`、`0xC4−0x8C = 0x38`）**互不相等**，
> 正是"物理缺失引脚留下的空洞"，所以**不存在统一公式**。
> ⚠️ 请以上表 / SVD 实测值为准，勿自行推导。
> 好消息：`Gpio_SetAfMode`（`【DDL】Drivers/hc32f005/src/gpio.c:206`）用 `enPort`（0/0x40/0x80/0xC0）做补偿，
> **调用方无需关心这些洞**（验证见 §4.3）。

## 4. Q2：`Pxx_SEL` 的位宽与含义；它是不是 AF 号？

### 4.1 位宽 = **3 bit（0–7）**

- `【DDL】Project/hc32f005/hc32f005.h:933-936` `stc_gpio_p01_sel_field_t { __IO uint32_t SEL : 3; }`（其余 15 个引脚定义完全相同，`:938-1011`）。
- `【DDL】HC32F005.svd:3976` `P01_SEL resetMask 0x7`；`:3981-3982` `<msb>2</msb><lsb>0</lsb>`；**16 个 `Pxx_SEL` 全是 `mask=0x7`**。

### 4.2 每档对应什么功能？→ **是 AF 号，但映射表不在本地**

- DDL 明确定义了 8 档 AF 枚举：`【DDL】Drivers/hc32f005/inc/gpio.h:112-122`
  `en_gpio_af_t { GpioAf0=0 "GPIO功能", GpioAf1..GpioAf7 }`，
  且 `gpio.h:109-110` 头注释直接写：**"具体功能及含义请参考用户手册GPIO复用表"**。
- ⇒ `SEL` 就是 **Alternate Function 编号（AF0–AF7）**，`Gpio_SetAfMode(port,pin,af)` 就是把 `af` 写进该引脚的 `Pxx_SEL.SEL`。
- ⇒ **AF 号 ↔ 具体外设功能的对照表 = ⚠️未确认（本地无据，需用户手册 GPIO 复用表）**。
  本地数据手册只给出"某引脚支持哪些功能"（§9），**不含编号**。

### 4.3 `Gpio_SetAfMode` 与 `Pxx_SEL` / `Pxx_AFR` 的关系（gpio.c 实现代码）

> **重要更正**：本 DDL **不存在 `Pxx_AFR` 寄存器**。全工程搜索 `AFR` 无任何结果；
> `hc32f005.h` 里与复用有关的寄存器**只有 `Pxx_SEL`**（`【DDL】Project/hc32f005/hc32f005.h:2709-2788`）。请勿按 STM32 的 `AFR` 概念套用。

`Gpio_SetAfMode`（`【DDL】Drivers/hc32f005/src/gpio.c:204-209`）：

```c
en_result_t Gpio_SetAfMode(en_gpio_port_t enPort, en_gpio_pin_t enPin, en_gpio_af_t enAf)
{
    *((uint32_t*)(((uint32_t)((&(M0P_GPIO->P01_SEL)) - 1u) + enPort) + (((uint32_t)enPin)<<2))) = enAf;

    return Ok;
}
```

**地址算式拆解（这是本 DDL 最"绕"的一点，值得记住）**：

| 步骤 | 表达式 | 说明 |
|---|---|---|
| 基准 | `&M0P_GPIO->P01_SEL` | = `0x40020C00 + 0x04` |
| 减 1 **字节** | `- 1u` | 注意是 **减 1 字节**，得到 `0x40020C03` |
| 加端口 | `+ enPort` | `enPort` 就是 `0x00/0x40/0x80/0xC0`（`gpio.h:85-88`） |
| 加引脚 | `+ (enPin << 2)` | 每引脚 **4 字节**步进，`enPin` 是**物理位号**（P14 → `4`、P27 → `7`、P36 → `6`） |
| 结果 | `*(uint32_t*)` 赋值 | 写 `SEL` 字段（3 bit，低 3 位有效） |

**逐点验证（算式 ⇒ 实际偏移，全部命中）**：

| 调用 | 算式 | 得到偏移 | 目标寄存器 |
|---|---|---|---|
| `Gpio_SetAfMode(GpioPort0, GpioPin1, …)` | `0x03 + 0x00 + 1*4` | `0x07` → 对齐到 `0x04` | P01_SEL ✓ |
| `Gpio_SetAfMode(GpioPort1, GpioPin4, …)` | `0x03 + 0x40 + 4*4 = 0x53` → 对齐 `0x50` | `0x50` | P14_SEL ✓ |
| `Gpio_SetAfMode(GpioPort1, GpioPin5, …)` | `0x03 + 0x40 + 5*4 = 0x57` → 对齐 `0x54` | `0x54` | P15_SEL ✓ |
| `Gpio_SetAfMode(GpioPort2, GpioPin7, …)` | `0x03 + 0x80 + 7*4 = 0x9F` → 对齐 `0x9C` | `0x9C` | P27_SEL ✓ |
| `Gpio_SetAfMode(GpioPort3, GpioPin6, …)` | `0x03 + 0xC0 + 6*4 = 0xDB` → 对齐 `0xD8` | `0xD8` | P36_SEL ✓ |

> 说明：`-1` 造成的 `+3` 字节错位会被 `<<2` 的 4 字节对齐"吸收"，最终仍精确落在 4 字节对齐的 `Pxx_SEL` 上。
> **等价的可读写法**：`P01_SEL 偏移 + enPort + (enPin<<2)`，其中 `P01_SEL` 偏移为 `0x04`，`enPort` ∈ {0,0x40,0x80,0xC0}。
> ⚠️ 依赖"Port1 基址正好比 Port0 的 pin3 之后多 0x40"这一事实，属**脆弱写法**，但与本芯片寄存器映射吻合（已验证 5 个采样点）。

### 4.4 `Gpio_Init` 会清掉 AF 吗？→ **会，且必须在 `Gpio_SetAfMode` 之前调用**

`Gpio_Init` 第 2 行就复位了 `SEL`（`【DDL】Drivers/hc32f005/src/gpio.c:98-102`）：

```c
en_result_t Gpio_Init(en_gpio_port_t enPort, en_gpio_pin_t enPin, stc_gpio_cfg_t  *pstcGpioCfg)
{
    //配置为默认值,GPIO功能
    SetBit((uint32_t)&M0P_GPIO->P0ADS + enPort, enPin, FALSE);          // 1) 清模拟模式 → 数字口
    *((uint32_t*)(((uint32_t)((&(M0P_GPIO->P01_SEL)) - 1u) + enPort) + (((uint32_t)enPin)<<2))) = GpioAf0; // 2) AF 强制回 0
    ...
```

**调用顺序约束（硬性）**：

| 顺序 | 原因 |
|---|---|
| ① `Sysctrl_SetPeripheralGate(SysctrlPeripheralGpio, TRUE)` | 先开 GPIO 时钟（`gpio.h` 无此 API；见 `hc_uart.c:15`、`hc_timer.c:53`） |
| ② `Gpio_Init(...)` | 设定方向/驱动/上下拉/开漏；**同时把 ADS 清 0、把 `SEL` 清 0** |
| ③ `Gpio_SetAfMode(...)` | 写入目标 AF；**必须在 Init 之后**，否则会被 Init 覆盖为 `GpioAf0` |

- 反例（会失效）：先 `SetAfMode` 后 `Gpio_Init` → AF 被清为 0，引脚退回普通 GPIO。
- 模拟功能（ADC/VC/LVD 输入）**不要**调 `Gpio_Init`——应调 `Gpio_SetAnalogMode()`，它置 `PxADS` 位
  （`【DDL】Drivers/hc32f005/src/gpio.c:187-192`）。二者对 `ADS` 的语义相反。
  ⚠️ `Gpio_SetAnalogMode` **不会**清零 `SEL`，所以从复用状态切模拟时建议显式 `Gpio_SetAfMode(..., GpioAf0)`。
- DDL 印证样例：`【DDL】User/Application/src/hc_uart.c:19-25`（先 `Gpio_Init` 后 `Gpio_SetAfMode`）、
  `User/Application/src/hc_timer.c:57-62`（同）。

### 4.5 `GPIO_GPSZ` 是什么？

`【DDL】Drivers/hc32f005/inc/gpio.h:74` `#define GPIO_GPSZ (0x40u)` —— 端口块步进 0x40，无其他用法（全工程仅此一处定义）。

SF 是"**把某个内部/外部信号源接到某个外设输入端**"的第二层多路选择，`GpioSf0` 恒等于"`PX_SEL` 里已经配好的那个功能"。

|---|---|---|

### 6.9 SF 机制怎么用（工作模型）

```
        ┌──────────────── Pxx_SEL.SEL (AF0..AF7) ───────────────┐
引脚 ──►│ 第一层：引脚功能多路（Gpio_SetAfMode）                 │──► 某外设端口（如 TIM4_CHA）
        └───────────────────────────────────────────────────────┘
        ┌──────────────── CTRL2/3/4 的 xxx_SEL (SF0..SF3) ──────┐
        │ 第二层：给"输入类"外设挑信号源（Gpio_Sf*Cfg）          │──► 外设的 Gate / Capture / ECA 输入
        └───────────────────────────────────────────────────────┘
```

- **两层都指同一外设输入时，`SF0`（= `GpioSf0`）表示"就用 `PX_SEL` 里配好的那个引脚"**（`gpio.h:279` 注释："SF0:PX_SEL的配置功能"）。
- 典型用法：`Gpio_SfTimCCfg(GpioSfTim4CA, GpioSf0)` ⇒ TIM4 的 CHA 捕获源 = P23/P34/P26 中由 `Pxx_SEL` 选定的那个。若想改用别的引脚做捕获源，则传 `GpioSf1..GpioSf3`。
- `GpioSfTimGCfg/GpioSfTimCCfg/GpioSfPcaCfg` 都是**读-改-写**（先 `&= ~(0x3<<pos)` 再 `|=`），因此**不会破坏同寄存器内其他通道的设置**（`gpio.c:389-390, 406-407, 423-424`）。
- ⚠️ SF1–SF3 具体映射到哪个引脚 **未确认**（本地无据）。

| 晶振 | 引脚 | 证据 |

| **XTLI / X32KIN**（外部低速输入，32.768 kHz） | **P14** | `【DS】AN_GPIO.txt:5-11`（D2）"X32KIN → P1.4" |
| **XTLO / X32KOUT**（外部低速输出） | **P15** | `【DS】AN_GPIO.txt:5-11`（D2）"X32KOUT → P1.5" |

**DDL 代码印证**：启外部高速时钟时，驱动**直接操作 GPIO 模拟位**清掉 P01/P02：
`【DDL】Drivers/hc32f005/src/sysctrl.c:155-157`
```c
M0P_SYSCTRL->PERI_CLKEN_f.GPIO = TRUE;
M0P_GPIO->P0ADS |= 0x06u;          // 0x06 = bit1|bit2 → 把 P01、P02 置为模拟（晶振）模式
M0P_SYSCTRL->SYSCTRL0_f.XTH_EN = bFlag;
```
⇒ **P01/P02 一旦启用 XTH 就不能当数字 IO**（除非改用内部 RCH，并把 ADS 清 0 + `Pxx_SEL=0`）。

**复用为 IO 的官方流程**（`【DS】AN_GPIO.txt:5-11`，D2 §3.3）：
1. `PERI_CLKEN.GPIO = 1`；2. `P0ADS`/`P1ADS` 相关位清 0（数字口）；3. `P01_SEL/P02_SEL/P15_SEL/P14_SEL = 0`；4. 设 `P0DIR/P1DIR` 方向。
> 注意 AN 用 `P00DIR`（笔误，应为 `P0DIR`），且第 3 步顺序与"先 Init 后 SetAf"一致。

**本工程实际时钟路径**：走**内部 RCH 16 MHz**，**不用外部晶振** → P01/P02/P14/P15 **理论可释放为 GPIO**（`system_hc32f005.c:85-94`）；但 `board_stkhc32f005.h:64` 仍定义 `SYSTEM_XTH (32*1000*1000u)`（仅宏值，未启用）。

### 7.7 复位 / SWD 调试口占用哪些引脚

| 功能 | 引脚 | 证据 |
|---|---|---|
| **RESETB** | 复用为 **P00**（数字输入） | `【DS】D1:1110-1115` "RESETB / P00 / 复位输入端口，低有效 … P00 数字输入"；`【DS】AN_GPIO.txt:1-7`（D2 §3.1）"Reset 引脚可以复用为输入端口 P0.0" |
| **SWCLK** | **P31** | `【DS】D1:1020` `P31/SWCLK`；`【DS】D1:1417` "SWCLK"（P31 功能列表） |
| **SWDIO** | **P27** | `【DS】D1:1023` `P27/SWDIO`；`【DS】D1:1397` "SWDIO"（P27 功能列表） |

**复用为 IO 的官方流程**（`【DS】AN_GPIO.txt`，D2 §3.2）：
1. `PERI_CLKEN.GPIO = 1`；2. **`SYSCTRL1.SWD_UIO` 使能**；3. **`P27_SEL.SEL = 0` 且 `P31_SEL.SEL = 0`**；4. 设 `P2DIR.P27` / `P3DIR.P31` 方向。
> 注意：**AN 把 SWDIO 与 SWCLK 的引脚写反了**（AN 说"P27_SEL 与 P31_SEL"但没指明谁是谁；数据手册明确 **P31=SWCLK、P27=SWDIO**）。
> ⚠️ **两者必须同时释放**（AN 要求两个 SEL 都置 0），因此释放 SWD 会**同时失去 SWCLK 和 SWDIO**。
> ⚠️ "复用 SWD 后在线调试/下载失效"（`AN_GPIO.txt` 注意事项）；`【DDL】Drivers/hc32f005/inc/sysctrl.h:203` `SysctrlSWDUseIOEn = 8u` 对应 `SYSCTRL1.SWD_USE_IO`（`hc32f005.h:1982`）。

**RESET 复用为 P00 的 DDL 侧支持**：
- `【DDL】Drivers/hc32f005/inc/sysctrl.h:201-204` `SysctrlEXTHEn`、`SysctrlSWDUseIOEn` —— ⚠️ **没有 `ResetUseIO` 枚举**，尽管 `hc32f005.h:1981` 有 `RES_UIO` 位域。
- 复位源标志：`【DDL】Drivers/hc32f005/inc/reset.h:122` `ResetFlagMskRstb = 1u<<7u`（"RESET脚 复位"）。
- ⇒ 需要 P00 作输入时，可用 `Sysctrl_SetFunc()` 系列直接写 `SYSCTRL1.RES_UIO`（DDL 有 API 但枚举缺失，见 §11）。
- ⚠️ **硬件注意**（`AN_GPIO.txt`）：复用 Reset 为 P00 时，上电瞬间该脚**不能为低电平**，否则程序无法运行；**即使不复用也不能悬空**。

| **外部晶振** | `XTHI`=**P01**、`XTHO`=**P02**、`XTLI/X32KIN`=**P14**、`XTLO/X32KOUT`=**P15** | **4**（本工程不用晶振 → 可释放） | `【DS】D1:1024,1027`；`【DS】AN_GPIO.txt:5-11` |
| **可自由使用的 GPIO** | **P03, P23, P24, P25, P26, P33, P34, P35, P36** | **9** | 见下 10.2 |
| **（若释放晶振脚）额外可用** | **P01, P02, P14, P15** | **+4** | — |
| **（若释放 SWD）额外可用** | **P27, P31** | **+2**（须同时失去调试能力） | `AN_GPIO.txt` §3.2 |
| 合计 GPIO（不含 P00） | 16 | 16 | `【DS】D1:908` |

### 10.2 结论（按 3 档场景）

| 场景 | 可用 GPIO | 引脚清单 | 说明 |
|---|---|---|---|
| **A. 保守（保留 SWD + 保留 Reset + 不用晶振）** | **9** | P03, P23, P24, P25, P26, P33, P34, P35, P36 | 可直接动手画原理图的最小可用集 |
| **B. 常规（保留 SWD + 不用晶振，P00 不当作 GPIO）** | **9**（=A） | 同上 | **推荐按此设计**：留 SWD 便于调试 |
| **C. 激进（释放晶振 + 释放 SWD，量产板）** | **13** | A 档 9 个 + P01, P02, P14, P15 + P27, P31 | 释放 SWD 后**无法在线调试/下载**，需预留串口下载恢复通道 |
| **D. 极限（含 P00 作输入）** | **+1 个纯输入**（P00） | C 档 + P00 | P00 无输出能力（`hc32f005.h:1013-1019` 无 DIR 位）；且上电不得为低 |

> **对原理图设计最关键的数字：不牺牲调试口、不用外部晶振时，真正可自由分配的 GPIO = 9 个**，
> 即 **P03 / P23 / P24 / P25 / P26 / P33 / P34 / P35 / P36**。
>
> ⚠️ 这 9 个里还有 3 个被本工程占用：**P35+P36 = UART1**（`hc_uart.h:14-17`）、**P23+P24 = TIM4 捕获/或作 PWM**（`hc_timer.h:14-17`）。
> ⇒ **实际剩余 5 个**（P03, P25, P26, P33, P34）。
>
> ⚠️ 还须扣除 `VCAP` 占用（不是 GPIO）+ QFN20 的 Exposed Pad。

### 10.3 电机驱动可用 PWM 引脚的可行性检查（重要）

若要用 **TIM4/5/6 做三相 PWM（每相 CHA+CHB 互补）**，需要的 6 个引脚必须**同时**满足"落在 §10.2 A 档 9 脚内"：

| 通道 | 可选引脚（§7.1） | 其中落在 A 档 9 脚内的 |
|---|---|---|
| TIM4_CHA | P34, P26, P23 | ✅ P34 / P26 / P23 |
| TIM4_CHB | P35, P24, P23, P15 | ✅ P35 / P24 / P23（P15 需释放晶振） |
| TIM5_CHA | P36, P34, P27, P25 | ✅ P36 / P34 / P25（P27 需释放 SWD） |
| TIM5_CHB | P26, P24, P33, P15 | ✅ P26 / P24 / P33 |
| TIM6_CHA | P36, P27, P23, P02 | ✅ P36 / P23（P27 需释放 SWD；P02 需释放晶振） |
| TIM6_CHB | P35, P32, P03, P02 | ✅ P35 / P03（P32 是 SWD 区？—— **P32 在 A 档内**✅；P02 需释放晶振） |

> **结论**：**在 A 档 9 个可用 GPIO 内，可以凑出 6 路独立 PWM（TIM4_CHA/CHB + TIM5_CHA/CHB + TIM6_CHA/CHB）**，例如
> `TIM4: P34+P35`、`TIM5: P36+P33`、`TIM6: P23+P03`（仅示意一种组合，实际受 AF 号与引脚冲突约束，**必须先确认 AF 表**）。
> ⚠️ 上表只保证"引脚功能支持"，**未验证 AF 号是否可同时配置**（例如同一引脚在两张表里出现就必须二选一）。**此项必须查用户手册 GPIO 复用表后才能定案**。
